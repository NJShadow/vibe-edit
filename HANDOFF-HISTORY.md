# Vibe Edit — version history

Detailed change log, newest first. Each entry records the ROOT CAUSE, how it was
measured, and why the fix is shaped the way it is — not just what changed. When a
piece of code looks odd, the reason is usually here.

For architecture, invariants and workflow see `HANDOFF.md`.

(Entries up to v4.0.0 use the app's former name, Cutroom.)

---

- **v4.10.4** **Precise exports stay smooth when the window is covered** (`review-fixes.js stale`). Reported: a 23.976 fps clip (AV1 WebM, trimmed import, H.264 proxy, Precise, CRF 22, slow) exported "way less smooth". Measured the user's MP4: 497 frames, 196 of them repeats of the previous one, the rest skipping 1–4 source frames — but frame i still ≈ source frame i (no drift), i.e. the RIGHT moment with a STALE picture. The user had switched to a browser during the render. Reproduced cleanly on Linux Electron (513/513 distinct frames, also with the window hidden — software decode), so the Windows path: a fully covered window is reported hidden (native occlusion), Chromium stops presenting video and refreshes the element's frame from a slow background timer, `requestVideoFrameCallback` never fires and `seekMediaExact`'s 200 ms fallback let the previous frame be drawn. Fixes: (1) `main.js` turns off `CalculateNativeWinOcclusion` and occluded-window/renderer backgrounding (backgroundThrottling:false didn't cover it); (2) `seekMediaExact` (during an export) waits until the frame the element HOLDS contains the target — `new VideoFrame(el).timestamp` is the held frame's start time, independent of presentation (`_heldTs`, `_awaitFreshFrame`: re-seeks at 0.3/0.9 s, accepts a decoder that moved off the old frame and settled for 120 ms — uneven frame spacing — gives up at 1.5 s and counts it); (3) the Precise renderer reports any frames that never arrived (`_freshStats`, a toast). Healthy exports: every frame passes the check at once (513 checked, 0 waits). Test hygiene: wedge check 1 samples 2 s of output (the page is busy right after an import).

- **v4.10.3** **A media element that stops answering seeks is replaced** (`review-fixes.js wedge`). Reported: an MP3 clip that was muted, deleted and dragged back from Media played silently while the L/R meter moved. Inspected live in the user's desktop app (DevTools console): the file's `<audio>` was stuck `seeking` at readyState 1 — a single seek didn't land in 3 s, while a NEW `Audio()` on the same blob seeked in a few ms (readyState 4). The meter reads import peaks, so it kept moving. The app's playback loop made it worse: `_driveEl` re-seeked every frame once the element was 0.22 s behind, and a pending seek reports its target as `currentTime`, so a slow seek was restarted every ~0.25 s forever. Not reproducible on Linux Chromium (MP3/WebM/Opus, browser and Electron, with the real UI). Fixes: `_wireSeekRedraw` timestamps the start of each seek wait (`el._skT`, cleared on seeked/canplay); `_elWedged(el)` = still seeking at readyState < 2 for 2.5 s (never during an export); `_elRevive(id)` builds a fresh element on the same file (keeps the app's `_` markers, not transient seek state), puts it in `els[id]`, drops the id's live audio chain (bound to the old element) so `wireAudio` rebuilds it on the next play, pauses the old one, at most once per 4 s per media; checked in `syncMediaPlayback` and `syncMediaSeek`. `_elSeekTo` (forward playback seeks) won't restart a seek still in flight for 0.9 s.

- **v4.10.2** **Same-track transitions crossfade the SOUND too** (`review-fixes.js axfade`). v4.10.1 made the picture real (A keeps playing past its out point under B's In transition) but A's sound still stopped dead at the cut. Now, for every pair the picture makes (a VIDEO clip A ending exactly where B starts on the same track — `_xfPairKey`, so compound inner clips pair on their own track — and B has an In transition), A's sound continues past its out point with `_xfSrcTime`'s rule (A's end speed incl. a ramp's end speed, its direction, stopping at the edge of the imported source) and fades out equal-power (cos) over the In transition's length (`_trInDur` = exactly what `transitionAt` plays), while B's sound fades in (sin). Sound clips LINKED to A that end with it / linked to B that start with it (Detach audio, Merge & sync, Ctrl+L; a split gives each side its own link) cross the same way; a J/L cut's audio doesn't line up with the cut, so it's left alone. A photo/color A has no sound (nothing changes); a photo/color B just lets A's sound fade out under it. Plain audio clips have no transitions in this app, so they are never paired on their own.
  **One plan, three mixers.** `_axfPlan()` (core, next to `_clipLiveVol`) returns `{info, tails}`: per clip id `{xi}` (fade in) / `{xe,xo}` (fade out) / `{of}` (a tail), and the continuations as VIRTUAL clips (`_axfTail`: id `A.id+'~xf'`, `_axfOf:A`, start = the cut, inPoint = A's source at the cut (window-relative), speed = A's end speed, no ramp/kf/link, volume = A's (keyed) volume at the cut). Each mixer plays tails like any clip, so speed, pitch (Preserve pitch on → time-stretch, off → record-style), reverse, effects and track mute/solo go through the existing code paths: the preview (`syncMediaPlayback` — tails last in the claim order; a split clip's tail plays on its own `_auxEls` element, created and parked 0.6 s before the cut so A's sound doesn't gap; reversed tails use `_revVoice`), the offline mix (`renderAudioOffline`; a normalized clip's tail reuses its clip's gain) and the FFmpeg graph (`buildAudioMixSpec` → spec clips carry `env`, `desktop/audio-filter.js` `envExpr` turns it into a per-sample `aeval` curve in place of the two `afade`s). Every level goes through `_axfFade(c,t)` (preview gains, meter, offline curve via `setValueCurveAtTime` at 1 ms, FFmpeg expression) — clips not in a crossfade get exactly `fadeFactor` / the old afade nodes, so existing projects mix bit-identically.
  **Fades don't double.** Each side's level is the SMALLER of the clip's own fade and the equal-power curve, never their product. A's Fade out now ends where A's sound ends (the end of the transition) instead of at the cut: a fade out no longer than the transition changes nothing; a longer one keeps its slope (so A is a little louder just before the cut than before v4.10.2) and meets the crossfade. B's Fade in still starts at B's start; longer than the transition, it wins where it is lower. Clip volume/keys (incl. ducking keys) and mute apply as before; the tail holds the volume A ends with.
  **Limits:** the FFmpeg direct mix still hands volume keys, ramps and reverse to the browser mix (unchanged), and now also a crossfade whose outgoing clip is normalized (loudnorm would level the short tail on its own). A tail that reaches the source edge stops there (a hard stop, like the picture's held frame). In the preview the tail is a second element started at the cut, so on a slow machine its first few ms can lag; Preserve-pitch time-stretch runs separately for A and its tail (a WSOLA seam at the cut in the offline mix). The waveform on the timeline doesn't draw the tail.
  **Tests:** `review-fixes.js axfade` — ffmpeg-made tones (A 440 Hz, B 1000 Hz, and one file 440→1000 Hz for a split clip), Dissolve 1 s: Goertzel levels at ¼/½/¾ of the transition match cos/sin within 0.8 dB (½: both −3.0 dB) and each tone is < −40 dB outside it — offline mix, the app's spec through audio-filter.js + real FFmpeg, linked audio clips (both paths), unlinked audio clips unchanged, record-style 2× (tail at 880 Hz), pitch-kept 2×, source edge, long/short fades (min rule), volume/mute, color B; live preview gains (Web Audio nodes of B, A's tail on its own element, pre-rolled aux for a split clip) at sin/cos of the playhead. With the plan disabled, every crossfade check fails (the plain-cut controls still pass).
  **Keyframes follow speed changes** (`review-fixes.js kfspeed`, user decision). Every edit that changes a clip's speed keeps its source span and changes its length, but the keys (`c.kf`, clip-local seconds) used to stay at their old times — so a 2× clip lost its later keys past its end and every animation landed on different footage. Now `kfSpeedSnap(c)` before the change and `kfSpeedRetime(c,snap)` after (core, next to `rampTlToSrc`) move each key through SOURCE time: local t → progress through the source span under the old timing (through the old ramp, `rampPAt`) → local t under the new one (`rampUAt`, its exact inverse); constant speed is just t×newDur/oldDur (1×→2× halves). Wired into: the Speed slider/typed value (and each linked partner, `_linkedSpeedPartners`), the Speed reset arrow, Paste attributes → Speed (every selected target; speed is now applied before Transform/Audio so keys pasted from the source arrive unchanged), and `proRampLinked` — the one door for ramp presets, curve drags, "None"/reset/palette Remove (removing a ramp keeps the length but moves every source moment, so keys move too), partners included. Bezier handles (`key.b`) and exact fragments (`key.e`) are segment fractions and need nothing. Compounds: their own keys scale like any clip, in step with `_cmpRetime`'s ÷speed for the clips inside (unchanged). **Reverse is not retimed**: keys stay put on the timeline (the usual NLE convention). Fades and transition lengths stay in timeline seconds, clamped to the new length. A ducked clip's record (`c.duck`, `proDuckRetime`) is re-timed with its keys when they are still its own, so Remove ducking still restores the pre-duck keys. One undo step, restored exactly. Every key check fails with the retime disabled.
  **Same-file continuations on two tracks** (`xfade` 7): checked that the hidden decoders behind the v4.10.1 picture crossfade are per CONTINUING CLIP (`_xfUse` keyed by clip id; idle ones pooled per URL and dropped with the file), so the same file continuing on two tracks at once shows two correct pictures (Precise and paused), never more than two elements, all released after — the check fails if the decoders are shared per media. (Two ordinary clips of one file visible at once: see the next paragraph.)
  **Follow-ups: linked speed everywhere, and one file shown twice at once** (`review-fixes.js kfspeed` 10–11, `samemedia`). (1) The Speed reset arrow and Paste attributes → Speed changed only the clip itself, so linked sound drifted. All three speed edits (slider/typed value, reset arrow, paste) now go through one core door, `speedChangeLinked(c,fn)` (next to `_linkedSpeedPartners`): partners covering exactly c's span with c's timing (same start, length, speed, direction, ramp — the `proRampLinked` rule, found before the change) get an exact copy of the result, ramp included (so a reset removes the ramp from both); a J/L-offset partner follows the slider's rule (same factor, offset scaled, own ramp scaled — or removed when c's was); every partner's keys re-timed with `kfSpeedSnap/kfSpeedRetime`; one undo step. (2) Two ordinary video clips of the SAME file visible at the same moment (picture-in-picture on V1/V2, overlapping copies, a freeze frame over its own clip, one inside a compound and one outside) shared `els[mediaId]`, so one showed the other's frame (and in the Precise export the last seek won). `_smPlan(t)` now picks, per media, the clip that keeps `els` — the one that had it last (`_smPrev`, so a clip entering on top never makes the playing one re-seek), else the lowest visible track — and every other visible clip of that file draws from its own hidden, muted decoder (`_smUse`, keyed by clip id; the crossfade's per-URL pool, refactored into `_hdEl/_hdRelease/_hdPrune/_hdSweep` and capped at 2 idle decoders per file). A clip at exactly the owner's frame (a duplicate used as a blurred background) just shares `els` — no extra decoder. Driven exactly like the crossfade decoders: seeked exactly when paused and per frame in the Precise export (`seekMediaExact` → `_smSeekExact`; the owner alone seeks `els`), played with drift correction during playback / Fast export (`_smSync`, from `_xfSync`; pre-rolled 0.45 s before a clip enters; reversed → chained seeks unless the reverse cache serves it), released when not needed (both kinds are pruned BEFORE either acquires, so they reuse each other's idle decoders). `syncMediaSeek`/`syncMediaPlayback` give each plan owner first claim on `els` (`_smOrder`); `prerollMedia` also seeks the secondaries at the export start. The compositor computes the plan once per frame at depth 0 (`_smCur`) and compound layers reuse it (their virtual clip ids match `playClips()`); `clipSourceFrame` (chroma Pick, tracking) returns the same element. The reverse cache and frame blending still replace the source per clip (a blended/cached frame is drawn even while a new secondary decoder is loading). Decoders follow the file behind the media (proxy ↔ original, full-quality export) and are dropped with it. Sound-only elements are left out. **Sound** was already per clip and is unchanged: in the preview the owner plays on `els`, the other clip on its own `_auxEls` element (v4.9.1); the offline and FFmpeg mixes mix each clip on its own; the hidden picture decoders are always muted, so nothing doubles or goes missing. **Tests:** `samemedia` (ramp25.webm, level = source frame) — PiP Precise/paused, owner = lowest track / the one already playing, exact copies share (0 extra decoders), freeze/reversed/2× copies, compound (pair inside; one inside + one outside), `clipSourceFrame`, frame blending on the second clip, playback (pre-roll, drift, each clip its own frame), proxy↔original swap, leak check (3 copies → 3 decoders, ≤ 2 idle after, 0 once the file is gone), and the sound (tones: offline mix, spec through real FFmpeg, preview gains/aux). With the plan reduced to the old sharing every picture check fails (the sound checks are guards and pass either way); `kfspeed` 10–11 fail on the previous build. Test hygiene: the `xfade` 5 and `samemedia` 7 playback checks play at half speed (the sandbox draws ~5 fps; the old full-speed run caught 1–4 frames and was flaky on the previous build too).

  **Ramp and keyframe curve hit-testing** (`dev/pro-ramp.js`, `dev/pro-curves.js`): `pos()` re-measures the canvas when its size no longer matches the cached W/H (a ResizeObserver callback can lag a click made while the section or inspector column is still animating open, so the first grab of a point intermittently missed) and excludes the border; found as a 1-in-4 flake in sweep2 check 10.

- **v4.9.0** LUT LIBRARY, SCOPES, FRAME BLENDING/MOTION BLUR, COMPOUND SPEED, CAM++ SPEAKERS (Opus 5.5 session). Measured in `tests/pro-grade.js` (and CAM++ in real Electron by `desktop-pro.js`).

## 12. KEY BUG-FIX INSIGHTS / GOTCHAS (so you don't re-learn them the hard way)

1. **Selected-chip contrast:** never hardcode text color on accent backgrounds. Use `var(--accent-ink)`. All 16 themes are verified for accent/ink contrast ≥ ~4.6 and text/bg ≥ ~12.8.
2. **Playhead is viewport-anchored vertically, content-positioned horizontally.** Don't make it a plain child of the scroller or its cap scrolls away.
3. **Scrollbar clicks must not seek.** Any pointerdown handler on a scroll container must exclude the scrollbar strips + non-primary buttons.
4. **The precise export uses a lossy VP9 intermediate.** Only the lossless path (quantizer 0) escapes it. Don't claim any other FFmpeg target is "lossless."
5. **Cover art = attached-picture video stream** in music files. For pure-audio conversion always `-vn`.
6. **High-sample-rate audio (96/192kHz) won't decode in Chromium.** Always resample to 48kHz on conversion/proxy.
7. **Web Audio has no native pitch shifter.** The Jungle dual-delay shifter is the live solution; FFmpeg asetrate+atempo is the export solution. Both validated.
8. **drawFrame is the single render path** — preview and export share it. Add visual features there once.
9. **Light themes register in THREE places:** THEMES array, JS `light=[...]` array, and the `.clip .cname/.cdur` CSS selectors.
10. **Always `assert s.count(old)==1`** in patches (or the exact expected count when deliberately multi-replacing). Ambiguous matches silently corrupt or no-op.
11. **Copy cutroom.html → cutroom-app/app/index.html on every ship.** Forgetting means the desktop app ships stale. Verify with md5sum — three identical hashes.
12. **`ctx.letterSpacing`** IS supported in Chromium/Electron (used for meme/text tracking). Set before measureText so wrapping accounts for it; reset to '0px' after.
13. **FLAC compression level ≠ quality** — all levels are lossless; level only trades size/speed.
14. **`aNormalize` is export-only**; everything else previews live.
15. **(new)** Every new slider needs a `HINTS` entry; every new export format needs an `FMT_TIPS` entry; every new interactive element needs a title — run the tooltip coverage test before shipping UI changes (§9).
16. **(new)** Every new modal must declare its dismiss behavior explicitly (§10). Promise-returning dialogs MUST register `setOverlayDismiss`; busy-refusing handlers must re-register themselves.
17. **(new)** In puppeteer tests, top-level `let` globals (`FF_AVAILABLE`, `captionRunning`) are reachable only via **bare** assignment inside `evaluate`; `window.X=` creates a decoy property.
18. **(new)** No double quotes inside `title` strings (they're injected via template literals into innerHTML-parsed attributes); entities like `&amp;` are fine and render as the character.
19. **(new)** The tooltip coverage test must check `el.closest('[title]')` — title inheritance from `.ctl` containers and `<label>`s is the intended mechanism, not a gap.

20. **Canvas 2D cannot mix CSS filter functions with `url()`** — `'brightness(1.2) url(#f)'` draws NOTHING (silently, [0,0,0,0]). Either pure CSS functions or a single `url()`. This is why the grading engine folds all legacy props into the SVG filter.
21. **SVG filters default to `linearRGB`** — always set `color-interpolation-filters="sRGB"` or the numbers are dramatically wrong (a 0→0.5 table maps 128→92 instead of 64).
22. **Grading props may be `undefined` on old clips** (project load does no defaults merge). Every read must go through `gv(p,k)`. Adding a new grade prop = add to `defaultProps` + `GRADE_DEFAULTS` + `HINTS` + the reset case + `FX_KEYS` + `applyFilterPreset`'s reset list, and include it in `gradeFilterFor`'s cache key.
23. **Canvas filters apply per draw operation** (SourceGraphic = only what that call draws). A sharpen/glow filter sees the drawn frame, not the composited canvas — and a test that draws two rects through a convolve filter will see no edge between them.
24. **Grain must not trigger the url() path** — it is a canvas overlay (`gradeFilterNeeded` excludes it), keyed to `floor(state.time*24)%3` so preview and precise export match exactly. When testing animation, pick times whose tile indices actually differ (1.0 and 1.5 both give index 0!).
25. **Self-copying a canvas onto itself stalls hard** — `cx.drawImage(cv, sx,sy,..., dx,dy,...)` where source and dest are the same canvas measured **335ms/frame** software-rendered (read-after-write hazard forces a full readback per call). Effects that displace slices of the frame below them (oldfilm gate jitter, VHS line-warp/tracking, glitch slices) must copy from a **shared per-frame snapshot** (`_ovSnap(W,H)` — one `drawImage(cv)` into an offscreen at the start, then sample from the offscreen). After the fix VHS runs 0.7ms/frame. One snapshot per `drawFrame`, sized lazily.
26. **Chromium switches the canvas to a software backend after the first big `getImageData`**, which changes antialiasing on the NEXT rasterization — so a determinism test that draws once, reads, draws again, reads will see a spurious full-frame diff on draw #2 that is an *environment artifact, not app nondeterminism*. Warm the backend with one throwaway full read, then assert steady-state equality across draws #2 and #3. (This is distinct from gotcha #23 which is about filter scope.)
45. **The container filesystem resets between sessions — /home/claude is scratch.** Restore ritual: `cp outputs/cutroom.html → working copy; unzip outputs/cutroom-desktop.zip → cutroom-app; npm i puppeteer-core @sparticuz/chromium in uitest`. The verify-*.js suites do NOT survive; each suite's assertions are documented in its §11 entry — recreate the relevant ones before touching their subsystems. `addTrack(kind)` mutates TRACKS without returning the new track (find by id-exclusion). MediaRecorder webm reports Infinity duration until seeked — always decode-fallback for durations of recorded media.
44. **Guards must never refuse silently, and thresholds must respect frame rates.** The 50ms split guard predated fps-awareness and swallowed single-frame edits at 23.976/24fps without a word. Any interaction guard added to editing verbs (split/trim/nudge/etc.) needs (a) a floor derived from real use (frames, not round numbers) and (b) a toast on refusal. When a user reports "the button does nothing", grep for silent `return`s first.
43. **Tracker v3 invariants (all test-pinned).** Scale changes ONLY via the smoothed anchor sweep (never per-frame probes); anchor refreshes are AGE-GATED (≥24 frames) or they re-absorb the very drift they exist to measure; coast keys are speculative and must be discarded on hard stop; thinning must stay JOINT over position and scale. When touching stepFrame, run the sparkle-noise and coast scenarios first — they model the exact real-footage failures that motivated v3.
42. **Adaptive templates absorb slow scale drift — measure scale against a pristine reference.** The 12% template blend is what makes position tracking robust to lighting/angle change, and EXACTLY what makes per-frame scale probes blind to gradual growth (0.3%/frame is invisible to a template that updates 12%/frame). The periodic tz0/tn0 reference sweep in stepFrame is the counterweight; don't remove either half. Scale hysteresis (+0.015 probes, +0.006 sweep) is what keeps constant-size subjects phantom-free — both margins are load-bearing and test-pinned. The `.gshape` gizmo overlay must stay DOM (never canvas) so snapshots/exports stay clean.
41. **The tracker's coordinate mapping is frozen at t0 by design (v1).** `trackMotion` converts canvas↔source through the UNDERLYING clip's box AT THE START TIME; if that clip's transform animates during the span, tracked positions drift (a heads-up toast fires). Lifting this means re-evaluating `clipBoxCanvas(src,tt)` per frame in `toCan` — straightforward, listed as the first v2 item. Template matching's inherent limits (heavy rotation/deformation/occlusion of the SUBJECT) surface as honest confidence stops, not silent drift — keep the 0.42 threshold conservative. `_revSeek`'s instant path for non-media elements is load-bearing for test speed; don't "simplify" it away.
40. **Gap badges must never leave their gap; preview correctness is event-driven.** Any badge styling/size change must respect `maxWidth = gapPx−12` (set inline in renderGapBadges) or it re-covers the trim handles. The preview's stale-frame defenses are `_wireSeekRedraw` (seeked→redraw, wired in the sync loops — a NEW element creation path gets it automatically on first sync) and the pre-roll pass at the bottom of syncMediaPlayback (`el._preroll` keying; active elements clear it). If a future feature adds elements the sync loops don't visit, wire them explicitly.
39. **FFmpeg filtergraphs: never trim a mixed stream by timestamp.** `amix` inherits the FIRST input's pts base; a delayed (adelay) first input makes `atrim=0:D` guillotine everything before the delay. Rules now baked into `buildAudioFilter`: silent full-length bed is always amix's first input; `asetpts=PTS-STARTPTS` comes BEFORE the final pad; pads are BOUNDED (`apad=whole_dur=`) because infinite `apad` relying on downstream EOF can stall the graph. Any new native filter path must follow all three. The renderer's `_audioSpecSupported()` gate must grow alongside the spec: a clip feature the spec can't express (today: volume keyframes, reverse) must force the browser-WAV fallback or it silently disappears from exports.
38. **The audio rescue is a LAST-resort layer — keep its ordering.** Ladder (validated decodes) → `_rescueShortDecode` (element capture, only for the span clips need, aligned by NCC against the good region) → warning. The capture element is dedicated (same rule as the reverse cache, gotcha 35); `window._captureHook` is the test seam. If media loading ever changes URLs/proxying, the rescue inherits it via `m.url`. The header `#verBadge` must be bumped with APP_VERSION each ship — it exists precisely because a user ran a stale desktop build while we chased a "failed" fix.
37. **Export audio decodes must be VALIDATED, never trusted.** `decodeAudioData` can return a PARTIAL buffer under memory pressure (machine-conditional — reproduced only on user HW). Any new decode call must check `duration ≥ media.duration−1.5` and either retry down the ladder or record `_decodeShort` so the mix warns. Long sources decode at 48 kHz on purpose (halve the allocation); don't "optimize" back to mix-rate decodes for everything. Schedule spans stay clamped to the buffer.
36. **drawWave is a strip blit — keep it that way.** Any waveform styling change goes in `_waveStrip` (the per-media pre-render), not per-clip loops; strips key on height|theme|bucketCount and self-invalidate when peaks are rebuilt (N changes). `renderTimelineSoon` exists for bursty callers (zoom) — new high-frequency triggers of timeline rebuilds should use it, structural edits keep calling `renderTimeline` synchronously. `_inspShownId` must be nulled if a future path mutates the selected clip's SECTION SET without calling renderInspector (none do today).
35. **The reverse cache build must NEVER touch the live element.** All build seeking happens on the dedicated `_revMakeEl` clone; the live `els[mediaId]` is only ever parked (single seek to inPoint on cache-hit). If you extend the builder (e.g. higher-res tiers), keep that isolation — the v3.29.0 lesson is that sharing the playback decoder corrupts both the cache and the visible video.
34. **Reverse cache correctness hinges on the key.** `revCacheKey = mediaId|inPoint|span` — any edit that changes what source pixels a reversed clip shows MUST change one of those (trim/slip/speed all do). If a future feature alters content without touching them (e.g. per-clip source offset), add it to the key or reversed playback will show stale frames. Cached frames are downscaled (≤640×360) — the paused/scrubbed preview still uses the live element at full res; only in-motion reverse playback uses the cache, so the quality dip is confined to motion. Exports never touch the cache (they seek the real element frame-exactly).
33. **All media source-time math goes through `srcTimeFor(c,t)`.** Like liveProps, one door: a new seek/draw/export path computing `inPoint+(t−start)*speed` inline will silently ignore reverse. Reversed LIVE audio is muted by design (elements can't play backward); export audio reversal happens in renderAudioOffline's two branches — keep both when refactoring. The desktop `will-download` filter map in main.js must gain an entry when a new download file type is added, or it falls back to a generic single-extension filter.
32. **Region gizmo edges depend on the `cropable` gate in updateGizmo.** Edge handles are display:none unless the gate admits the clip type — a new clip type wanting edge handles must be added there AND given a branch in the gizmo edge handler (the media branch bails on `!b.m||!b.fit`). Feathering lives on the MASK (`_adjM` blur), not the effect — putting blur in `filterStr` instead softens the censored content, not the boundary.
31. **Stage overflow is intentional containment.** `#stage{overflow:hidden}` is the fix for gizmo handles covering panels at high zoom — do not remove it, and any future overlay meant to escape the stage (popovers etc.) must live OUTSIDE `#stage`. Pixelate has two render paths: `drawMediaMaybePix` (per-clip, both chroma branches) and the `_adjP` block in `drawAdjustLayer` (region censoring) — a new draw branch for media must route through the helper or pixelate silently vanishes there.
30. **All animatable prop reads go through `liveProps` — one door.** If you add a renderer or exporter that reads `c.props.x/scale/opacity/volume/rotation/y` directly it will ignore keyframes; read `liveProps(c,t)` (or `kfProp`) instead, and WRITE via `setAnimProp` so an animated prop gets a key instead of a dead base write. `clipBoxCanvas(c,t)` defaults to `state.time` — call sites that mean "base framing" (none currently) would need care.
29. **`cv.width` ≠ `state.project.w` while playing.** The playback-quality system halves the canvas during playback; anything needing true project dimensions must read `state.project.w/h` or call `_applyPreviewScale(false)` first (openProjectCrop does; export sets its own canvas and is guarded). Everything that works in canvas-relative fractions is automatically safe.
28. **Ranged exports slice a full-length audio mix.** `renderPrecise` mixes audio over the whole project and offsets the Opus chunk loop (`_a0`), re-zeroing timestamps — do NOT "optimize" by mixing only the range (clip scheduling is absolute) and do not re-enable `ffmpegAudio` for ranged exports (the native handoff renders full-project audio → desync).
27b. **Project crop preserves absolute pixels, then re-origins.** `remapClipForCrop` reproduces each clip's exact on-screen size/position on the smaller canvas by back-solving the transform from `clipBoxCanvas` (old dims) — NOT by keeping frame-relative %s (which would re-frame the content). Must run before `cv.width/height` change. Color clips are intentionally skipped so backgrounds re-fill; meme/overlay/audio auto-adapt. If you add a new visual clip type, decide explicitly whether it preserves-absolute (add to the remap allowlist) or re-fills (skip it).
27a. **Inspector sections are wrapped, never rewritten.** The accordion (`inspAccordionHTML`) transforms each section's existing HTML string with a single `.replace('<div class="sec"', …)` — every section opens with exactly `class="sec"` (verified: 20/20, nothing after the quote), so the replace is unique per section. If you add a section whose wrapper has extra classes (`class="sec foo"`), the replace won't match and it won't fold — keep the bare `class="sec"` and add classes elsewhere. Collapsing is CSS `display:none`, so collapsed controls remain in the DOM (tests and any querySelector still find them) — never gate logic on a section being visually open.
27. **Overlay determinism is seed-based, not RNG-stateful.** Every overlay uses either `_ovHash(a,b,c)` (one-shot, no state) or a `_mulberry(seed+epoch)` re-seeded per time-epoch — never a persistent RNG advanced per frame — because scrubbing/export can call `drawFrame` at arbitrary non-monotonic times. Per-clip random constants (`_ovArr`) are cached by clip id and are stable; the cache is a mulberry *prefix* so shrinking a clip's particle count doesn't reshuffle the survivors.

To **add a control to an existing effect**: add one line to its `defs`/`cols`/`tgl` — `ovv(c,k)` null-safety means old saved projects transparently get the default. Do NOT add overlay props to `defaultProps`.

- Styled/instant custom tooltips (progressive replacement reading the same `title` attributes — §9).
- Keyboard accessibility pass (focus outlines, arrow-key navigation of chips) — `title` doesn't help screen readers; `aria-label`s could be added by the same mechanism as titles.

## 14. HOW TO REASON ABOUT THIS PROJECT (distilled judgment — read this even if you skim elsewhere)

These are the meta-level heuristics that have kept this project stable across ~30 versions. They're not in the code; they're the decision style behind it.

1. **Measure before you edit; test before you claim.** The tooltip task looked like "sprinkle titles around." The right first move was building the coverage test, which turned a vague goal into an exact worklist (321 raw gaps → ~90 unique elements → 0 missing, provable). Whenever a task is "make X comprehensive/complete," build the completeness checker FIRST and drive the work from its output. You get a regression test for free.
2. **Restraint is a deliverable.** In the v3.20.0 review, main.js was audited and deliberately NOT changed: it's validated on real hardware, and Electron IPC is untestable here. "I reviewed it and it's sound, so I left it alone" is a legitimate, valuable outcome — and the user explicitly values that honesty over performative churn. Resist the urge to refactor working code to look busy; every untested diff in the Electron/WebCodecs layers is real risk.
3. **The honesty invariant is a product feature.** When a capability can't be verified or guaranteed, the app refuses loudly (lossless gate) and the ship notes disclose it (WebCodecs quantizer shape, real-HW-only validation). Never write UI copy, tooltips, or summaries that overstate certainty. If you find yourself writing "always"/"perfectly"/"lossless" — stop and check whether the code can actually promise that.
4. **Read the failure before trusting the tool.** Two v3.20.0 examples: the coverage test's first "failures" were actually correct behavior (title inheritance) — the *test* needed fixing, not the app; and the caption test failed because `window.captionRunning` doesn't reach a top-level `let`. When a test fails, first ask "is the assertion wrong?" before patching the app to satisfy it.
5. **Bugs are often in the seams, not the features.** The Esc-hang bug lived in the interaction between three individually-correct pieces: a keydown handler, a dismiss registry, and a promise-based dialog — written at different times, never composed. When reviewing, trace cross-cutting flows (what happens to EVERY open dialog on Esc? on backdrop? during export?) rather than auditing features in isolation.
6. **Prefer one mechanism over N copies.** Tooltips for ~40 sliders went through ONE `HINTS` map and two helper functions, not 40 template edits — which also created the maintenance contract (new slider → new HINTS entry → test enforces it). When adding anything repetitive, build the map/helper and let the test enforce completeness.
7. **Exact-string patching is a safety system, not a chore.** The `assert count==N` discipline has repeatedly caught would-be silent corruption (template strings recur!). Never regex-patch this file; never patch without the assertion; write tricky patches to /tmp files.
8. **Split every feature along the sandbox boundary at design time**, not after: a browser-testable half (UI state, config objects, DSP via OfflineAudioContext) and an FFmpeg-testable half (run the actual filtergraph on synthetic media with the sandbox ffmpeg, compare PCM/frame MD5s). If a design can't be split that way, flag the untestable part in the ship notes explicitly.
9. **Don't trust remembered API details in the untestable zones.** WebCodecs per-frame options, Electron dialog quirks, Chromium codec support — these vary by version and CANNOT be confirmed here. Where correctness depends on them, gate with feature detection (`isConfigSupported`) and fail loudly, exactly as the lossless path does. Write down the residual risk (§7's pattern) so the user knows what to watch for.
10. **The user is the integration environment.** Ship notes should tell them precisely what to try on real hardware and what symptom would indicate which failure. That converts their testing time into diagnostic signal (this is how the audio-crackle saga was eventually cracked — debug WAVs designed to discriminate hypotheses).
11. **Keep this document alive.** Update it at every ship: version header, §11 history entry, §13 pending. It is the project's only durable memory across sessions — treat letting it go stale as a shipping failure equal to forgetting the app/index.html copy.
